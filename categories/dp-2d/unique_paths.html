Unique Paths

Grid DP ⏱ O(m·n) time 💾 O(m·n) space

Problem

A robot starts at the top-left of an m × n grid and wants to reach the bottom-right. It can only move right or down. How many unique paths are there?

Input:  m = 3, n = 7
Output: 28

Intuition

How did the robot arrive at any cell? Only two ways exist: from above or from the left. So the number of paths into a cell is the sum of the paths into those two neighbors — dp[r][c] = dp[r−1][c] + dp[r][c−1].

The first row and first column are base cases: there's exactly one way to reach them (march straight right, or straight down). Fill the table row by row and the bottom-right cell accumulates the total. It's Climbing Stairs stretched into two dimensions.

Full Explanation

Every cell in the grid asks the same small question: how many ways can the robot possibly get here? Since the robot only moves right or down, it can only have arrived from the cell directly above or the cell directly to the left. Adding those two answers gives this cell's answer — no path is missed and none is counted twice.

Cells in the first row or first column can only be reached one way, by marching in a straight line, so they seed the table with ones. Filling the rest row by row, each cell is a single addition of two already-known values. When we reach the bottom-right corner, it holds the total number of unique paths. This is the two-dimensional version of the Climbing Stairs recurrence, and since each cell only looks up and left, the whole table can be compressed to a single rolling row for linear space.
