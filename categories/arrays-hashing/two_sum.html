Two Sum

One-pass HashMap ⏱ O(n) time 💾 O(n) space

Problem

Given an array of integers nums and an integer target, return the indices of the two numbers that add up to target.

Each input has exactly one solution, and you may not use the same element twice.

Input:  nums = [2,7,11,15], target = 9
Output: [0, 1]
Because: nums[0] + nums[1] = 2 + 7 = 9

Intuition

Brute force checks every pair — O(n²). The key insight: for each number x, we don't need to search for its partner; we only need to ask "have I already seen target − x?"

A HashMap answers that in O(1). Walk the array once: check if the complement is in the map — if yes, done; if no, store the current number and move on. One pass, no double-checking.

Full Explanation

We solve Two Sum with a single pass and a HashMap. For each number we compute the complement — target minus the current number. If the complement is already in the map, a previously-seen number pairs with the current one, and we return both indices immediately. Otherwise we record the current number and its index in the map and continue.

Because each element is visited once and every map operation is constant time on average, the algorithm runs in linear time with linear extra space. The one-pass version also naturally avoids using the same element twice: we only ever match against numbers seen strictly before the current index.
