Network Delay Time

Dijkstra's Algorithm ⏱ O(E log V) time 💾 O(V + E) space

Problem

A signal starts at node k in a directed, weighted network. times[i] = (u, v, w) means travelling u → v takes w time. Return the time for the signal to reach all nodes, or -1 if some node is unreachable.

Input:  times = [[2,1,1],[2,3,1],[3,4,1]], n = 4, k = 2
Output: 2

Intuition

The answer is the largest shortest-path distance from k — the last node the signal reaches. Shortest paths from one source in a weighted graph is exactly Dijkstra's algorithm.

Dijkstra is BFS upgraded with a priority queue: always expand the closest unvisited node next. When a node is popped for the first time, its distance is final — nothing cheaper can appear later, because everything still queued is already farther. Popping a node, we relax its outgoing edges: if going through it beats a neighbor's best-known distance, update and requeue.

Full Explanation

The signal reaches every node along its shortest path, so the total delay is the largest of the shortest-path distances from the source. Dijkstra's algorithm computes exactly that. We keep a best-known distance for every node — infinity at first, zero for the source — and a priority queue that always hands us the closest unfinished node.

When a node comes off the queue for the first time, its distance is locked in: every other candidate path must pass through nodes that are already farther away, so nothing can improve it. We then relax each outgoing edge — if reaching a neighbor through this node is cheaper than its current best, we record the better distance and add the neighbor to the queue with its new price. Stale queue entries are harmless; they're skipped when popped because the node is already visited.

When the queue empties, every reachable node has a final distance. If any node is still at infinity the signal can never get there, so we return minus one; otherwise the answer is the maximum distance in the table — the arrival time at the last node the signal touches.
