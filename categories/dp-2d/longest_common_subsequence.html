Longest Common Subsequence

String-vs-String Table DP ⏱ O(m·n) time 💾 O(m·n) space

Problem

Given two strings, return the length of their longest common subsequence — characters in the same relative order, but not necessarily contiguous. Return 0 if none exists.

Input:  text1 = "abcde", text2 = "ace"
Output: 3  ("ace")

Intuition

Compare the strings one prefix pair at a time. Let dp[i][j] = LCS length of the first i chars of text1 vs the first j chars of text2.

If the two current characters match, they extend the best answer of both shorter prefixes: dp[i][j] = dp[i−1][j−1] + 1 (diagonal + 1). If they don't, one of them is dead weight — drop whichever hurts less: max(dp[i−1][j], dp[i][j−1]). Row 0 and column 0 are zeros (empty prefix has nothing in common). The finished table even remembers the subsequence itself — walking it backwards spells it out.

O(m·n)
Time — one cell per prefix pair
O(m·n)
Space — the table (two rows possible)

Full Explanation

The table compares every prefix of one string against every prefix of the other. Cell i, j answers: what's the longest common subsequence using only the first i characters of text one and the first j characters of text two? The zeroth row and column are zero because an empty prefix shares nothing.

When the characters at the current pair of positions match, that character can safely end the common subsequence for both prefixes, so the answer is one plus the diagonal neighbor — the best result before either character was considered. When they differ, at least one of the two characters cannot be part of the answer, so we take the better of ignoring one or the other: the max of the cell above and the cell to the left.

After filling the table, the bottom-right cell holds the length. To recover the actual subsequence we walk backwards from that corner: on a character match we collect the letter and step diagonally; otherwise we follow whichever neighbor holds the larger value. The collected letters, read in order, are the longest common subsequence itself.
