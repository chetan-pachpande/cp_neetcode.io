Binary Tree Level Order Traversal

BFS with a Queue ⏱ O(n) time 💾 O(n) space

Problem

Given the root of a binary tree, return the values of its nodes as a list of levels — grouped left to right, level by level, top to bottom.

Input:  root = [3,9,20,null,null,15,7]
Output: [[3], [9,20], [15,7]]

Intuition

"Level by level" is exactly what breadth-first search gives you for free, as long as you know where each level ends. A plain queue processes nodes in level order, but doesn't naturally tell you the boundary between one level and the next.

The fix: before draining the queue for a level, snapshot its current size. That size is exactly how many nodes belong to this level. Pop exactly that many, collect their values, and enqueue their children — which land after everything already queued, ready to form the next level.

Full Explanation

We do a standard breadth first search using a queue, starting with just the root inside it. The trick to grouping nodes by level is to record the queue's size at the very start of each round — that count tells us exactly how many nodes belong to the level we're about to process, because every node currently in the queue was enqueued during the previous level's processing.

We then dequeue exactly that many nodes, one at a time, adding each one's value to the current level's list and enqueuing its children as we go. Because children are always added to the back of the queue, they never get mixed into the level currently being drained — they patiently wait to form the next level. Once we've dequeued the recorded count, that level list is complete and gets appended to the result, and the process repeats until the queue is empty.
