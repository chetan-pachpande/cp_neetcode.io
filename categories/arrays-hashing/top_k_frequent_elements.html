Top K Frequent Elements

Bucket Sort ⏱ O(n) time 💾 O(n) space

Problem

Given an integer array nums and an integer k, return the k most frequent elements. Answer may be in any order.

Input:  nums = [1,1,1,2,2,3], k = 2
Output: [1, 2]

Intuition

A heap-based approach gives O(n log k), but there's a neat trick: a value's frequency can never exceed n, the array length. That bounds the range of possible frequencies, which means we can use bucket sort.

Count each number's frequency, then place each number into buckets[frequency] — a bucket per possible count, index 0 to n. Walk the buckets from highest frequency down, collecting numbers until we have k of them. No comparisons, no heap — just counting and one linear sweep.

Full Explanation

We first count how often each number appears using a HashMap. Since no number can appear more than n times, we know every possible frequency fits in the range zero through n. That lets us build an array of buckets, one bucket per possible frequency, and drop each number into the bucket matching its count.

To find the k most frequent numbers we simply walk the buckets from the highest frequency down to the lowest, collecting numbers as we go, and stop as soon as we have k of them. Because both the counting pass and the bucket pass are linear in the size of the input, the whole algorithm runs in O(n) time, trading the O(n log k) of a heap-based approach for a small amount of extra bucket space.
