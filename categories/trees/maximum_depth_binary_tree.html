Maximum Depth of Binary Tree

Post-order Recursion ⏱ O(n) time 💾 O(h) space — call stack

Problem

Given the root of a binary tree, return its maximum depth — the number of nodes along the longest path from the root down to the farthest leaf.

Input:  root = [3,9,20,null,null,15,7]
Output: 3

Intuition

The depth of any node is just 1 + the deeper of its two subtrees. That's a recursive definition, so we let recursion compute it directly: a null node has depth 0, and every other node's depth is 1 + max(left depth, right depth).

We compute this bottom-up — post-order: find the left subtree's depth, find the right subtree's depth, then combine. By the time we return from the root call, we've touched every node exactly once.

Full Explanation

The depth of a tree rooted at any node is one more than the deeper of its two children's depths. A null node contributes a depth of zero, which is exactly the base case we need to make the recursion bottom out cleanly at the leaves.

For every node we first recurse into the left child and the right child to get their depths, and only after both return do we combine them: one plus the larger of the two. This is a post-order computation — we need the children's answers before we can produce our own. Since every node is visited exactly once and does constant work combining its children's results, the whole algorithm runs in linear time, with recursion depth bounded by the height of the tree.
