Validate Binary Search Tree

Bounds Propagation ⏱ O(n) time 💾 O(h) space — call stack

Problem

Given the root of a binary tree, determine if it is a valid binary search tree: every node's left subtree contains only values less than it, every right subtree only values greater than it — and this must hold for every node, not just its immediate children.

Input:  root = [10,5,15,null,null,6,20]
Output: false  (node 6 passes its local check against parent 15, but 6 < 10 breaks the whole-subtree rule)

Intuition

Checking a node only against its direct parent isn't enough — a node deep in a right subtree must still be greater than every ancestor it descended from on the left. So each node needs a valid range (lower, upper), not just a single comparison.

Start the root with range (−∞, ∞). Descending left tightens the upper bound to the parent's value; descending right tightens the lower bound. If any node's value falls outside its inherited range, the tree is invalid — immediately, no need to look further.

Full Explanation

A common mistake is checking each node only against its immediate parent, but that misses violations from higher ancestors. The correct approach threads a valid range through the recursion: every node is checked against a lower bound and an upper bound inherited from all of its ancestors combined, not just its direct parent.

The root starts with an unbounded range, negative infinity to positive infinity. Recursing into a left child tightens the upper bound to the current node's value, since everything in a left subtree must be smaller. Recursing right tightens the lower bound the same way. If a node's value ever falls outside its inherited range, we've found a violation and can return false immediately — the recursion doesn't need to check anything else. If every node passes its check, the tree is a valid binary search tree.
