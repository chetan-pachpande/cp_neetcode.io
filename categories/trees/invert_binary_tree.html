Invert Binary Tree

Recursive Swap ⏱ O(n) time 💾 O(h) space — call stack

Problem

Given the root of a binary tree, invert it — every node's left and right children are swapped, recursively — and return the root.

Input:  root = [4,2,7,1,3,6,9]
Output: [4,7,2,9,6,3,1]

Intuition

Inverting the whole tree is just swapping the children of every single node. There's no clever trick — the recursion does all the work.

At each node: swap left and right, then invert whatever ended up on each side. The base case is a null node — nothing to swap, so just return. Because every node is visited exactly once, this is linear in the number of nodes; the recursion depth matches the tree's height.

Full Explanation

Inverting a binary tree means mirroring it: every node's left subtree and right subtree swap places, all the way down. We handle this with straightforward recursion. If the current node is null, there's nothing to invert, so we simply return null — that's our base case.

Otherwise we swap the node's left and right pointers using a temporary variable, then recursively invert whatever is now on the left and whatever is now on the right. Because the swap happens first, the recursive calls naturally descend into the correct mirrored subtrees. Every node in the tree is visited exactly once, giving linear time, and the recursion depth never exceeds the height of the tree.
