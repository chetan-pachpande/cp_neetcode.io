Longest Consecutive Sequence

HashSet Streaks ⏱ O(n) time 💾 O(n) space

Problem

Given an unsorted array of integers nums, return the length of the longest consecutive elements sequence. Must run in O(n) — no sorting allowed.

Input:  nums = [100,4,200,1,3,2]
Output: 4  (the sequence [1,2,3,4])

Intuition

Sorting costs O(n log n). Instead, drop everything into a HashSet for O(1) membership checks, then only start counting a sequence from its true start — a number n where n − 1 is not in the set.

From each start, walk forward — n+1, n+2, … — as long as each is present, extending the streak. Because we only ever start from true sequence beginnings, every number is visited at most twice total (once for the predecessor check, once while extending), keeping the whole scan linear.

Full Explanation

We begin by loading every number into a HashSet, which gives constant time membership checks and automatically removes duplicates. The key trick is deciding where to start counting: we only begin a streak from a number n when n minus one is not present in the set. That guarantees n is the true beginning of its run, so we never redundantly recount the same sequence from the middle.

From each true start we walk forward, checking n plus one, n plus two, and so on, extending the current streak for as long as consecutive values exist in the set, and updating the best streak seen whenever the current one is longer. Because every number can only ever be the start of one streak, and every other number is visited during exactly one extension walk, the total work across the whole array stays linear even though there's a nested loop in the code.
