Design Add and Search Words

Trie + Wildcard DFS ⏱ O(26^d) worst case 💾 O(total characters)

Problem

Support addWord(word) and search(word), where search's word may contain '.' — a wildcard matching any single letter.

Ops:  addWord("bad"); addWord("dad"); addWord("mad")
Then: search("pad")→false; search(".ad")→true; search("b..")→true

Intuition

Store words in a trie exactly like before. The twist is searching: a plain letter still means follow one specific child, but a '.' means try every existing child — because we don't know which letter it stands for.

That "try every child" step is naturally a DFS with branching: recurse into each child on a wildcard, and succeed if any branch eventually matches the rest of the pattern. A plain letter just narrows the DFS to a single child instead of fanning out.

Worst case — d = wildcard count

Full Explanation

Words are stored in a standard trie. The interesting part is search, which we implement as a recursive depth-first walk over both the trie and the pattern string at the same time. At each step, if the pattern is exhausted, we succeed exactly when the current node is flagged as the end of a word.

Otherwise we look at the next character of the pattern. If it's a normal letter, we simply recurse into that one specific child — if it doesn't exist, this branch fails immediately. If it's a wildcard dot, we don't know which letter it represents, so we recurse into every existing child and succeed if any single one of those branches eventually succeeds. This branching is what makes wildcard search potentially expensive — each dot can multiply the number of paths explored by up to twenty-six — but in practice tries stay shallow and sparse, so it performs well.
