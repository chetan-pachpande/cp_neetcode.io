Two Sum II — Input Array Is Sorted

Converging Pointers ⏱ O(n) time 💾 O(1) space

Problem

Given a 1-indexed, ascending-sorted array numbers, find two numbers that add up to target. Return their indices [i, j] with i < j. Exactly one solution exists, and you may not reuse an element.

Input:  numbers = [2,7,11,15], target = 9
Output: [1, 2]

Intuition

Because the array is sorted, the HashMap trick from Two Sum isn't even the fastest option — two pointers use the ordering directly, with zero extra space.

Start lo at the left, hi at the right. Their sum is either exactly the target (done), too big (the largest value is too heavy — pull hi inward, since increasing lo could only make things worse), or too small (push lo inward). Each comparison eliminates one candidate, so the pointers converge in a single pass.

Full Explanation

Sorted order lets us reason about the sum of the two extreme pointers directly. Start one pointer at the very first element and the other at the very last. Their sum tells us exactly what to do next: if it equals the target we're done, if it's too large the right pointer is contributing too much and must move inward — since the array is sorted, no other pairing with that same right element could possibly work either — and if it's too small the left pointer must move inward for the symmetric reason.

Every step strictly shrinks the window between the two pointers, and since the problem guarantees exactly one solution, this converges to it in a single linear pass with no extra memory, beating even the HashMap approach used when the array isn't sorted.
