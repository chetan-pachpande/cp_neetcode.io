Word Search II

Trie-pruned Board DFS ⏱ O(mn · 4^L) worst case 💾 O(Σ L) for the trie

Problem

Given a board of letters and a list of words, return every word that can be formed by a path of adjacent cells (horizontally/vertically, no cell reused within one word).

Board: oaan / etae / ihkr / iflv
Words: ["oath","pea","eat","rain"] → ["eat","oath"]

Intuition

Searching for each word separately with its own DFS repeats a lot of work when words share prefixes. Instead, build one trie of all the words and run a single DFS from every board cell, walking the trie and the board together.

At each cell, only continue if the current letter is an existing child of the current trie node — this instantly prunes any path that can't possibly complete a word. Whenever the trie node we land on marks the end of a word, we've found it. Mark cells visited during the current path so we don't reuse them, then backtrack (un-mark) after exploring all four directions.

Full Explanation

We first insert every target word into a shared trie, storing the complete word itself at its terminating node so we can recognize a match instantly. Then we launch a depth-first search from every cell of the board, each starting at the trie's root.

At each step of the DFS, we check whether the board letter under our finger is a valid child of the current trie node; if not, this path cannot spell any remaining word, so we stop immediately — this pruning is what makes searching for many words at once so much cheaper than repeating a full search per word. If the trie node we've reached stores a complete word, we record it and clear that marker so it can't be reported twice. We temporarily mark the current cell as used, recurse into all four neighboring directions, and then restore the cell before returning, so other paths can still use it.
