Implement Trie (Prefix Tree)

Character-by-character Tree ⏱ O(L) per op 💾 O(total characters)

Problem

Implement a trie with insert(word), search(word) (exact match), and startsWith(prefix) (any word begins with this prefix).

Ops:  insert("apple"); search("apple") → true; search("app") → false
Then: startsWith("app") → true; insert("app"); search("app") → true

Intuition

Words that share a prefix should share the same path in a tree — that's the whole idea of a trie. Each node has up to 26 labeled children, one per possible next letter, plus a flag marking "a word ends here."

insert walks the word letter by letter, creating any missing nodes along the way, then flags the final node. search and startsWith both just walk the existing path for a string — the only difference is search also requires the end-of-word flag, while startsWith doesn't care.

O(L)
Time — L = word/prefix length

Space — shared prefixes cost nothing extra

Full Explanation

A trie stores strings by sharing common prefixes as a single path through a tree. Each node holds a map from character to child node; inserting a word walks that map one letter at a time, creating a new child whenever the next letter hasn't been seen yet at that point, and finally marks the last node as the end of a complete word.

Searching for an exact word and checking for a prefix use the identical walk — follow the letters down the tree, and if any letter is missing, fail immediately. The only difference comes at the end: search additionally requires that the node we land on is flagged as an end-of-word, while startsWith only cares that the path exists at all. Because the walk's length equals the string's length regardless of how many words are stored, every operation runs in time proportional only to the word or prefix being processed.
